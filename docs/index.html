edgegoat: edge case test inputs for JavaScript

The inputs that break code, ready to drop into your tests.

Curated, documented edge cases for time zones, daylight saving time, dates before 1970, unicode test strings, -0 and NaN, URLs, paths and JSON. Each one says why it breaks code. Works with Vitest, Jest, node:test and Mocha, in TypeScript or JavaScript.

Quick start

Edge cases in a real test suite

Every generator returns an array of { label, value, why, tags } objects, so it plugs straight into test.each. Filter with { tags: [...] } or { exclude: [...] }, pick zones with dates({ zone: 'Europe/Berlin' }).

TSdates.test.ts
import { describe, expect, test } from 'vitest';
import { dates, numbers, strings, withTimeZone } from 'edgegoat';
import { addDays, formatPrice, truncate } from './my-code';

describe('addDays keeps the wall clock across DST', () => {
  test.each(dates({ tags: ['dst'] }))('$label', ({ value, zone }) => {
    withTimeZone(zone, () => {
      expect(addDays(value, 1).getHours()).toBe(value.getHours());
    });
  });
});

test.each(strings({ tags: ['surrogate'] }))('truncate keeps $label whole', ({ value }) => {
  expect(truncate(value, 5).isWellFormed()).toBe(true);
});

test.each(numbers({ tags: ['sign'] }))('formatPrice($label)', ({ value }) => {
  expect(formatPrice(value)).not.toMatch(/^-0/);
});

How it works

Three steps, no setup

  1. 1

    Install

    Add edgegoat as a dev dependency. No configuration, no runtime dependencies.

  2. 2

    Pick the inputs

    Call a generator and filter it with { tags } or { exclude }: DST gaps, surrogate pairs, -0, path traversal.

  3. 3

    Run them with test.each

    Each case has a label for the test title and a why for the failure, so a red test tells you what broke.

Proof

Bugs these inputs found

Real bugs of this kind, fixed upstream by the author of edgegoat in widely used projects. The library packages the inputs that exposed them.

  • github/relative-time-element#384

    The "is this the current year?" check used UTC instead of the display time zone, so dates near New Year showed or hid the year incorrectly.

  • mozilla/pdf.js#22017

    util.printf dropped the sign of negative numbers greater than -1, such as -0.5.

  • google/budoux#1411

    Text segmentation could split a surrogate pair, producing half an emoji.

  • microsoft/vscode-js-debug#2423

    trimEnd style truncation could cut a surrogate pair in half.

  • salesforce/tough-cookie#644

    A cookie with an infinite max-age has to be treated as never expiring.

  • vuejs/core#15618

    A fix in the Vue 3 compat build.

  1. dates()

    unix epoch 1970-01-01T00:00:00.000Z

    1970-01-01T00:00:00.000Z

    Timestamp 0 is falsy, so `if (!time)` treats a valid date as missing, and west of UTC it is still 1969 locally.

  2. dates()

    1 ms before the epoch

    1969-12-31T23:59:59.999Z

    Negative timestamps: `ms % 1000` is -1, not 999, so splitting seconds and milliseconds with % and Math.floor disagree.

  3. dates()

    before 1970 with fractional seconds (1969-12-31T23:59:58.500Z)

    1969-12-31T23:59:58.500Z

    Truncating -1.5 s toward zero gives 23:59:59 instead of 23:59:58; Math.trunc vs Math.floor and integer division bugs live here.

  4. dates()

    moon landing 1969-07-20T20:17:40.123Z

    1969-07-20T20:17:40.123Z

    Negative timestamp with milliseconds: serializers that build "seconds.millis" from a negative value print a wrong or doubly negative fraction.

  5. dates()

    local mean time era 1850-01-01T00:00:00Z

    1850-01-01T00:00:00.000Z

    Before standard time, zones used local mean time with second level offsets (Sao Paulo was -03:06:28); getTimezoneOffset() reports whole minutes, so local arithmetic drifts by seconds.

  6. dates()

    year 0 (0000-01-01T00:00:00Z)

    0000-01-01T00:00:00.000Z

    Date.UTC(0, 0, 1) and new Date(0, 0, 1) map years 0 to 99 to 1900 to 1999, and toISOString() yields "0000", which "1 BC" formatting must handle.

  7. dates()

  8. dates()

    year 2038 limit 2038-01-19T03:14:07Z

    2038-01-19T03:14:07.000Z

    Last second representable as a signed 32 bit Unix time; anything that stores seconds in an int32 (or uses `| 0`) is fine here.

  9. dates()

    2038-01-19T03:14:08.000Z

    One second past the int32 limit: `(ms / 1000) | 0` wraps to 1901-12-13, and so do 32 bit database columns.

  10. dates()

  11. dates()

  16. dates()

  17. dates()

  72. strings()

    empty key

    "{\"\":1}"

    Valid; path based libraries (a.b.c syntax) cannot address it.

  258. json()

    escaped lone surrogate

    "\"\\ud800\""

    Valid JSON that decodes to malformed UTF-16; re-encoding to UTF-8 or a database fails.

  259. json()

    line and paragraph separators

    "\"a\u2028b\u2029c\""

    Valid JSON that was invalid in JavaScript string literals before ES2019, which broke JSONP and inline script tags.

  260. json()

    top level string

    "\"just a string\""

    Valid JSON since RFC 7159; code that assumes an object reads properties of a string.

  261. json()

    top level null

    "null"

    Valid JSON that parses to null; `const { a } = JSON.parse(text)` throws.

  262. json()

    whitespace around value

    " \n\t {\"a\":1} \r\n"

    Valid; byte or regex based detectors that check the first character for "{" fail.

  263. json()

    byte order mark prefix

    "\uFEFF{\"a\":1}"

    Windows tools write a BOM; JSON.parse throws on it, so strip it when reading files.

  264. json()

    trailing comma

    "[1,2,]"

    Accepted by JavaScript and JSON5, rejected by JSON.parse.

  265. json()

    comments

    "{\"a\":1 /* note */}"

    Common in config files (JSONC) but invalid JSON.

  266. json()

    single quotes

    "{'a':1}"

    JavaScript object syntax, not JSON.

  267. json()

    NaN literal

    "{\"a\":NaN}"

    Python json.dumps writes NaN by default, and JSON.parse rejects it.

  268. json()

    unquoted key

    "{a:1}"

    JavaScript object literal syntax that JSON does not allow.

  269. json()

    empty text

    ""

    An empty response body is not JSON; JSON.parse("") throws "Unexpected end of JSON input".

  270. json()

    raw control character in string

    "\"a\tb\""

    Unescaped tab inside a string is invalid JSON even though it looks harmless.

  271. arrays()

    empty array

    []

    Truthy even though empty; reduce without a seed throws and Math.max(...[]) is -Infinity.

  272. arrays()

    array with a hole

    [1, <hole>, 3]

    forEach, map and filter skip the hole but for...of and spread yield undefined, so the two styles disagree.

  273. arrays()

    explicit undefined

    [1, undefined, 3]

    Looks like the hole case when printed, but every iteration method visits it and `1 in arr` is true.

  274. arrays()

    length 5 with no elements

    [<hole>, <hole>, <hole>, <hole>, <hole>]

    new Array(5) has five holes: map returns holes, not values, and JSON.stringify writes nulls.

  275. arrays()

    huge sparse length (2^32 - 1)

    ["first", <hole>, <hole>, <hole>, <hole>, <hole>, ...] (length 4294967295)

    The maximum array length: cheap to create, but any loop to length or Array.from runs four billion times.

  276. arrays()

    NaN element

    [NaN]

    indexOf(NaN) is -1 while includes(NaN) is true; Set and Map treat NaN as equal to itself.

  277. arrays()

    -0 and 0

    [-0, 0]

    Set collapses them into one value and includes(-0) finds 0; Object.is tells them apart.

  278. arrays()

    numbers that sort as strings

    [10, 9, 1, 100]

    Default sort() compares strings, giving [1, 10, 100, 9]; always pass a comparator.

  279. arrays()

    undefined during sort

    [3, undefined, 1]

    sort() moves undefined to the end without calling the comparator, so comparators never see it.

  280. arrays()

    mixed number and numeric string

    [1, "1"]

    includes("1") and Set treat them as different, while == and loose lookups do not.

  281. arrays()

    nested empty arrays

    [[[]]]

    flat() and recursive flatten helpers must handle empty levels; String([[[]]]) is "".

  282. arrays()

    array with extra property

    [1, 2]

    for...in visits "extra" and Object.keys includes it, but length and JSON.stringify ignore it.

  283. arrays()

    frozen array

    [1, 2, 3]

    push and in place sort throw TypeError in strict mode; libraries that mutate input break.

  284. arrays()

    500000 elements (too many to spread)

    [0, 1, 2, 3, 4, 5, ...] (length 500000)

    Math.max(...arr) and fn.apply(null, arr) exceed the argument limit and throw RangeError.
